# 😈 Diablo Core Resilience Engine & WhatsApp Bot

A cold, high-performance, dark-themed Node.js clustering application built exclusively for headless deployments on **Render** and **Railway**. This engine combines a fast automation WhatsApp assistant with an ultra-hard, self-healing architecture capable of isolating and monitoring up to 55 critical runtime bug commands. 

Featuring a menacing, dark charcoal and glowing crimson **Diablo-themed terminal matrix dashboard**, the panel allows developers to stress-test platform limits via a web interface while keeping background tasks completely stable and isolated.

## 🛠️ Step-by-Step Cloud Deployment Guide

### 1. Initialize Variables
Before triggering your cloud build pipelines, go to your **Render** or **Railway** dashboard workspace control tab, open your **Environment Variables** options window, and configure the targeting number hook:
- **Environment Key Name**: `WA_PHONE_NUMBER`
- **Value**: `2348142334779` *(Always use pure numbers including area country dialing codes. Do not include spaces, hyphens, or a leading '+' symbol).*

### 2. Configure Cloud App Creation Settings
When configuring the deployment dashboard specifications, supply the following parameters to ensure proper setup routing:
- **Runtime Target**: `Node`
- **Build Core Command**: `npm install`
- **Start Execution Command**: `npm start`

### 3. Retrieve Your Linkage Pair Code
1. Once you save your configurations, the cloud host will immediately fetch your GitHub tree and trigger a build.
2. Go directly to your service's **Live Server Logs** or **Console output** window screen.
3. Within 10 to 15 seconds of the initialization sequence, look for this specific console metric log line:
   `🔥 YOUR WHATSAPP PAIRING CODE: XXXX-XXXX`
4. A secure native authentication request slide-banner will drop onto your mobile phone screen from WhatsApp. Tap it, clear your security lock screen, and input the exact 8-character string pulled from your cloud dashboard terminal logs to launch your bot live.

## 🔒 Safety and Isolation Guardrails
The engine encapsulates the entire Diablo HTML dashboard workspace layer cleanly inside a localized `http.createServer()` block boundary context. If a user inputs or interacts with any of the 55 heavy-duty operational bugs, **only that single sub-worker thread experiences the structural shutdown**. The master supervisor thread isolates the error, logs the stack information down to `debug.log`, and spins up a pristine worker session, ensuring your cloud service never drops offline.
